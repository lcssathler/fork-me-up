## Verification coverage through M3-S07

These narratives record the scope of verification, including limits on what the results prove.

M3-S03 makes `FMU-E-016` executable against two materially different consumers. The Codex lifecycle adapter and a stateless generic JSON process receive the same all-state DCP fixture and preserve identical allowlisted Claim capability/state/depth, Response Policy and expiry meaning. The generic path is separately installed with only the Protocol artifact and rejects invalid, expired, oversized or audience-mismatched packets without emitting free text. The evaluation proves structured behavior for these two consumers, not equivalent model prose or untested compatibility.

M3-S04 builds exact private tarballs for Protocol, Core and Community Provider, generates a temporary consumer lock from the official production dependency closure, and installs with lifecycle scripts disabled and offline cache use. Its seven artifact-only cases cover public version/operation rejection, owner portability, expected-generation conflict, explicit synthetic migration, prior-state recovery and Store/interchange separation. Clean verification begins with a fresh root `npm ci` and empty cache so the consumer's offline install relies only on the official lock-populated tree; the aggregate must not race another artifact build.

M3-S05 composes those installed packages into a temporary synthetic application and replaces one exact prerelease candidate graph with another built from the same reviewed source. It verifies Store reload, correction-preserving refresh, task context, export, managed deletion, package uninstall and retained source/export data on Windows, macOS and Linux. All required checks passed on [PR #43](https://github.com/lcssathler/fork-me-up/pull/43), and the four-job [post-merge main run](https://github.com/lcssathler/fork-me-up/actions/runs/34358697235) passed at `b5b8cef`. The version-only transition proves package replacement and persisted Store compatibility, not migration between different implementations, a packaged application or a public support window.

M3-S06 preserves full local utility with no configuration, account or network. An explicit closed owner configuration can instead use fixed GitHub GET metadata only after local Git proves shallow or an exact expected head authorizes eligible fallback. Synthetic tests cover authority binding, runtime-clock expiry independent of request metadata, visibility/head checks, hostile metadata, response/request/path/time ceilings, content-free degradation and process-memory reuse; the closing review additionally charges local Git time before granting the remote phase its smaller remaining deadline. All required checks passed on [PR #45](https://github.com/lcssathler/fork-me-up/pull/45), and its four-job [post-merge main run](https://github.com/lcssathler/fork-me-up/actions/runs/34370846888) passed at `24deb90`. This supports only selected public `github.com` commit metadata through an existing external `gh` login, not private repositories, arbitrary remotes, issues/pull requests, persistent remote caches or a general connector.

M3-S07 reexecutes the 48-case frozen M2 evidence experiment and independently scores three accepted calibration oracles across both current consumers for three repetitions. The clean report from implementation revision `ad1159f` passed 9/9 stable consumer pairs, 18/18 policy-adherent runs and 9/9 structured-meaning comparisons; it retained zero false `demonstrated` outcomes, 52/52 exact frozen-oracle attributions and 10/52 expected unknown attributions. Aggregate DCP size was 3,676 bytes against 5,145 portable-profile Export bytes, but the insufficient-evidence DCP was larger than its minimal Export, preventing a universal savings claim. Every DCP omitted complete Evidence records. The [benchmark record](../evaluations/M3_COMMUNITY_BENCHMARK.md#measurement-record) states that these are synthetic conformance results, not human accuracy, model-response quality, population performance, time saved or ranking. Complete aggregate, review and protected CI remain pending before integration.
