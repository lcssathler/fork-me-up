# ADR-0019: Bounded filesystem metadata collection

- Status: Accepted
- Date: 2026-09-05

## Context and task contract

M2-S01 is integrated on protected `main` at `01a33ff`, making M2-S02 the earliest eligible slice. Authenticated readback found successful post-merge CI, no open pull request, and no competing remote branch. This task is claimed by `feat/m2-s02-filesystem-collector`.

Traceability: `M2-S02`, `FMU-FR-002`, `FMU-FR-026`, `FMU-NFR-004`, `FMU-NFR-005`, `FMU-NFR-011`, `FMU-NFR-013`, `UC-05`, PROJECT_SPEC Sections 5.1, 7, 10, 12, 13, and 14, ARCHITECTURE Sections 3.2/3.3, 5.1/5.2, 8.1, 10, and 12, SECURITY_PRIVACY Sections 1 through 5 (especially T-01 through T-04), 8, 10, and 11, and ADR-0001/0002/0005/0008/0018. No `FMU-E-*` behavioral evaluation applies because this slice produces only private pre-Evidence filesystem metadata; it derives no Claim or Demand Profile, compiles no DCP, and changes no consumer or agent behavior.

The observable result is that a previously resolved M2-S01 authorization can collect deterministic, private metadata for supported documents, manifests, and source structure from synthetic local repositories. Every non-ignored entry is bounded and reauthorized at point of use; links, canonical escape, invalid/binary selected content, unsafe names, excessive entries/bytes/depth/time, and filesystem failure yield one typed content-free failure and no partial snapshot. Repository code, scripts, binaries, hooks, dependencies, URLs, and Git are never executed or followed.

In scope are one implementation-internal Community filesystem collector and Node filesystem port, a versioned private snapshot shape, a small fixed support/ignore taxonomy, bounded file reading and hashing, sanitized `package.json` signals, aggregate document/source metrics, injected time/filesystem boundaries, synthetic unit and real temporary-directory integration tests, this ADR, security/architecture/protocol documentation, changelog/README/roadmap synchronization, and the M2-S02/M2-S03 state proposal. Hard non-goals are Git metadata, repository inference, Evidence/Claim/Demand/Profile production, persistence/cache, correction, owner CLI, MCP/adapter changes, public schema, external dependency, network, submodule expansion, archive extraction, code execution, package installation, private-source access, release, or platform-compatibility expansion.

The snapshot begins at internal version `0.1.0`; it is not a public interchange contract, Profile Store, Portable Profile Export, Evidence record, or DCP. No released or persisted data requires migration. Allowed effects are local code/document edits, synthetic temporary trees, a short-lived branch, the authorized pull request/squash merge, and branch deletion. Stop on a higher-authority conflict, a read that cannot be constrained to the canonical root, raw content or absolute-path output, an execution/network path, a public-contract/dependency change, ownership conflict, unresolved high-severity finding, or protected CI failure.

Required verification covers authentic M2-S01 authority; point-of-use root/repository/file recanonicalization; case/platform containment; links/junctions and replacement detection; fixed ignores and nested-repository boundaries; deterministic traversal/order/output; supported and unsupported files; manifest sanitization; invalid UTF-8/binary/malformed JSON; malicious text/canaries; unsafe names; exact entry, per-file, total-byte, depth, and elapsed-time exhaustion; file growth beyond inspected size; missing/special/error states; all-or-nothing content-free failures; immutable/non-mutating output; no process/network/listener/import/URL/archive behavior; full project checks; clean lockfile install; dependency audit; Markdown links; complete-diff review; and protected pull-request plus post-merge CI.

## Decision

- Keep filesystem collection implementation-internal to `@fork-me-up/community-provider`. Protocol and Core receive no filesystem types or paths, and Profile Provider/MCP operations remain unchanged. The collector accepts only a live private authority value issued by the M2-S01 resolver, not a caller-forged lookalike.
- Traverse selected repositories sequentially and sort every directory and final output by code-unit order. Concurrency therefore remains one and never exceeds the configured maximum. Count every non-ignored observed entry against `maxFilesPerRepository`; stop before scheduling more work when the configured duration is exhausted.
- Reinspect and physically canonicalize the stored root and repository before traversal, then every directory and file before use. Require the current physical identities to match the authorized snapshot and require every canonical entry to remain within both its selected repository and named root. Reject all non-ignored symbolic links/junctions and special filesystem entries. Configuration-time authorization remains insufficient on its own.
- Use a narrow injected filesystem port. The Node implementation is limited to `lstat`, `realpath`, `stat`, `opendir`, and read-only file handles. A direct `lstat` probe checks only the fixed `.git` nested-repository marker before enumeration. Directory enumeration returns only bounded names; file reads revalidate the opened handle/path identity, stream no more than the granted byte remainder, and never invoke a shell, Git, package manager, hook, binary, URL, network primitive, or repository code.
- Never traverse `.git`, `.hg`, `.svn`, `node_modules`, or `.fork-me-up` directories. If a non-root directory contains a `.git` entry, treat it as a nested repository/submodule boundary and do not traverse any of its content. Other unsupported files are counted but not opened. Archives are unsupported and never expanded.
- Support a fixed initial taxonomy: Markdown/MDX/reStructuredText/AsciiDoc documents; selected Node, Python, Rust, Java, Gradle, Go, Ruby, PHP, Elixir, and requirements manifests; and a closed set of common source extensions. Selected files must be regular, within per-file and per-repository byte budgets, valid UTF-8, and free of NUL bytes. Invalid selected content fails the whole repository snapshot rather than becoming evidence.
- Emit only internal `filesystem-metadata-snapshot` `0.1.0` records. Every selected file includes a forward-slash source-relative path, fixed class/format or language, exact bytes read, lowercase SHA-256 content digest, and aggregate line/structure metrics. Source records add only a deterministic test-file marker. Document records add only heading/fence counts. Manifest records add format; `package.json` may add package type/private status, workspace count, and bounded sorted dependency/script names that match strict identifier syntax. Manifest values, package name/version, document headings, source text, snippets, absolute paths, usernames, and native errors are never emitted.
- Enforce all configured ceilings again. File-size inspection is advisory only; bounded read detects growth. Total-byte accounting advances from actual bytes read. An injected monotonic clock makes deadline behavior deterministic; the Node collector stops scheduling after expiry and fails if an operation returns after it. General filesystem calls are not cancellable on every supported Node platform, so a single in-flight metadata call may return after the deadline before the collector can fail; this limitation prevents a stronger hard-real-time claim.
- Return all-or-nothing immutable success or one of `invalid-input`, `path-unavailable`, `not-authorized`, `limit-exceeded`, `deadline-exceeded`, `binary-content`, or `invalid-content`, with only category and retryability. No failure returns repository/file identifiers, paths, source text, digests, partial records, native codes, messages, or stacks.

## Consequences and alternatives

M2 receives useful local project signals without creating claims or forwarding untrusted prose. Later Git, attribution, source-risk, Evidence, Claim, persistence, and cache slices can consume a deterministic private snapshot while retaining their own gates. Hashes enable equality/invalidation work later but remain private because hashes of source may still reveal information through guessing.

The collector intentionally reads complete supported text files up to the explicit per-file and total budgets to validate UTF-8, compute hashes, and derive aggregates. It does not read unsupported file content. Sequential traversal favors predictable limits over throughput. Fixed ignore rules may omit relevant generated/dependency structure; M2-S05 can classify supported collected paths but cannot claim evidence from ignored content. Hard links cannot be distinguished from ordinary authorized entries portably; the collector authorizes the canonical path used, not an inode's other names.

Returning raw document/manifest/source text, forwarding headings, parsing script values, evaluating manifests, honoring repository ignore files as authority, traversing `.git` or nested repositories, following links, extracting archives, executing Git, and silently returning partial results are rejected. Adding parser, glob, or walking dependencies is unnecessary for the fixed initial taxonomy.

## Validation

Run the pinned Windows Node.js/npm path and `npm run check`. Unit tests use injected authority, filesystem, and clock boundaries for deterministic success and every exhaustion/failure category. Integration tests create only temporary synthetic repositories and verify real files, malicious text, binary/invalid text, malformed manifests, ignored trees, nested repository boundaries, junction escape, depth/entry/size/total limits, and content-free failures. Static source checks reject process/network/listener/dynamic import, write, archive, URL-following, and repository-execution primitives. Review output fields for raw content and absolute paths, confirm no manifest/lockfile/public-schema change, validate Markdown links and dependency audit, then require protected pull-request and post-merge CI before the roadmap transition is authoritative.
