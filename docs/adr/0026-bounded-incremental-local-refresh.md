- Status: Accepted
- Date: 2026-09-07

## Decision

- Create an immutable opaque session backed by private process-local state. Bind it to authentic resolved repository, developer identity and source-risk configurations, exact complete repository/project mappings, extractor versions and explicit session budgets. Serialized/forged sessions cannot access the cache. Restart or changed configuration requires a new session and a cold refresh. Concurrent refreshes fail with a fixed busy result.
- Narrow live source authority only inside its issuer, selecting one existing repository/root and reducing collection duration. This never resolves or adds a path and never increases an original limit. Existing collectors still reauthorize at point of use.
- Before any reuse, perform a deterministic, bounded metadata-only walk beneath the selected canonical root/repository. Reject links, special files, replacement and unsafe names; enforce entry/depth/deadline bounds. Ignore the existing fixed dependency/state directories and stop at nested repository boundaries. Include the selected repository's complete standard `.git` metadata tree, without executing or opening its files. The opaque SHA-256 fingerprint covers safe relative membership, canonical identity and bigint device/inode/mode/size/mtime/ctime stamps; atime is excluded. Neither HEAD alone nor size/mtime alone is sufficient.
- Probe before and after full collection and reject changed fingerprints. Within a maximum five-minute content-observation age, unchanged fingerprints reuse the authentic filesystem/Git snapshots without parsing source or invoking Git. Hits update check time, never collection time. Expiry or explicit force triggers full collection. Metadata stamps detect ordinary changes, including same-length edits with restored mtime, but are not a transaction against active hostile same-user mutation; this retains ADR-0020's documented local trust limit. Fresh means successfully validated within the configured age, not cryptographic proof that source bytes remain unchanged.
- Bound each refresh by nonnegative, session-monotonic elapsed time, aggregate probe entries and full-collection count; bound retained cache JSON bytes including the prior derivation, and repository count. Charge ignored enumeration entries and reserve the full remaining allowance when enumeration fails. Invalid or throwing clocks latch a failure and clear source cache. Work is sequential and performs no automatic retry. Reduce each collector's duration to the remaining refresh budget and check time after every operation. An in-flight non-cancellable filesystem operation may complete after the deadline, but its result is not accepted.
- Expose per-repository opaque fingerprint, original collected time, current check-attempt time, `collection`/`memory-cache`/`none` origin, freshness and fixed invalidation reasons. Check time alone does not prove successful validation. Fresh describes cache usability; derived Evidence and Claims retain separate age semantics. Retain prior snapshots privately on transient unavailability or exhausted scheduling budgets, with explicit stale metadata; invalid source or changed-source collection failure evicts the affected cache entry. Stale/invalid records return no source payload. No failure echoes native errors or paths.
- Reassemble the complete fresh source set and rerun pure authorship, global duplicate/source-risk classification and Evidence/Claim derivation. Never cache final per-repository risk independently: adding or changing another source can alter duplicate support. If any repository is unavailable, stale or invalid, return explicit partial/stale/invalid state and withhold aggregate source payload and derivation; dropping a duplicate peer cannot promote the remaining source. Retained successful entries can be reused on the next refresh.
- Use the oldest full collection timestamp as the aggregate source observation time, current injected time for derivation, and an explicit stale threshold. Preserve the previous authentic successful derivation for deterministic invalidation; invalid/partial refreshes do not overwrite it. Only complete fresh output exposes authentic per-repository filesystem snapshots for the existing Demand producer. Persistence and correction-preserving owner composition remain later slices.

## Consequences and alternatives

The first cache is deliberately ephemeral and private. It reduces content parsing and Git process cost while still traversing metadata; it does not promise constant-time refresh or restart reuse. Complete `.git` metadata probing is conservative and may invalidate on unrelated Git maintenance or reject layouts/entry counts outside this bounded path. TTL, clocks and force are explicit; no cache hit silently renews evidence age. Authorization, identity/risk configuration and project mapping changes use a new session rather than reinterpreting old state.

HEAD-only reuse, trusting user-provided fingerprints, implicit watchers, arbitrary filesystem caches, persisted authentic-object bypasses, stale payload fallback on authorization failure, and partial-set claim promotion are rejected.
