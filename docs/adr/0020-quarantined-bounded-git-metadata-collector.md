# ADR-0020: Quarantined bounded Git metadata collection

- Status: Accepted
- Date: 2026-09-05

## Context and task contract

M2-S02 is integrated on protected `main` at `1ed1301`, making M2-S03 the earliest eligible slice. Authenticated readback found successful post-merge CI, no open pull request, and no competing remote branch. This task is claimed by `feat/m2-s03-git-metadata-collector`.

Traceability is `M2-S03`, `FMU-FR-002`, `FMU-FR-006`, `FMU-FR-018`, `FMU-FR-026`, `FMU-NFR-004`, `FMU-NFR-005`, `FMU-NFR-011`, `FMU-NFR-013`, `UC-05`, PROJECT_SPEC Sections 5.1, 7, 10, 12, 13, and 14, ARCHITECTURE Sections 3.2/3.3, 5.1/5.2, 8.1, 10, and 12, SECURITY_PRIVACY Sections 1 through 5 (especially T-01 through T-05), 8, 10, and 11, ENGINEERING Sections 3 through 6, and ADR-0001/0002/0005/0008/0018/0019. No `FMU-E-*` behavioral evaluation applies because this slice emits only private pre-Evidence Git metadata; identity assessment begins in M2-S04, and no Claim, Demand Profile, DCP, policy, or consumer behavior changes.

The observable result is that live M2-S01 authority can produce deterministic, private Git history metadata for a selected standard working-tree repository without allowing repository-controlled configuration or attributes to execute a command. The collector resolves a bounded local `HEAD`, validates the authorized object database, reads a bounded topological commit prefix and changed-path metadata through fixed Git plumbing, and emits only object IDs, timestamps, identity digests, parent relationships, coauthor digests, and safe repository-relative paths. Missing Git, unsupported repository layouts, invalid metadata, path escape/replacement, excessive objects/bytes/paths/time/output, or command failure return one typed content-free failure and no snapshot.

In scope are one implementation-internal Community Git collector, an injected bounded Git-command port and its Node subprocess implementation, safe control-file and object-tree inspection, a versioned private snapshot, synthetic unit tests and real temporary Git-repository integration tests, hostile configuration/attribute/metadata fixtures, this ADR, correction of the ADR index omission for ADR-0019, security/architecture/README/changelog/roadmap synchronization, and the M2-S03/M2-S04 state proposal. Hard non-goals are identity ownership decisions, bot/human classification, squash or pair-work conclusions, source-risk classification, Evidence/Claim/Demand/Profile production, persistence/cache, correction, owner CLI, Provider/MCP/adapter changes, public schema, dependency, remote/ref access, fetch, lazy object retrieval, submodule traversal, working-tree mutation, repository maintenance, private-source access, release, or platform expansion.

The snapshot starts at internal version `0.1.0`; it is not a public interchange contract, Profile Store, Export, Evidence record, DCP, or claim of authorship. No released or persisted data requires migration. Allowed effects are local code/document edits, synthetic temporary repositories, trusted temporary Git quarantine directories removed after each command, a short-lived branch, the authorized pull request/squash merge, and branch deletion. Stop on a higher-authority conflict, any uncontrolled repository configuration or external-command path, any Git read that can escape the authorized repository, raw identity/message/path diagnostics in output, a public-contract/dependency change, ownership conflict, unresolved high-severity finding, or protected CI failure.

Required verification covers authentic authority; point-of-use root/repository/`.git`/object-store authorization; standard-layout and detached/symbolic/shallow `HEAD`; SHA-1 and SHA-256 identifier validation; object-tree symlink/special/alternate rejection; object/count/byte/path/depth/time/output ceilings; history truncation; deterministic order and immutable output; merge parents; safe changed paths; author/committer/coauthor hashing; malicious commit messages, identities, paths, configuration, includes, aliases, hooks, fsmonitor, external diff, textconv, attributes, pagers, replace refs, promisor remotes, shell metacharacters, and canaries; Git unavailable/nonzero/timeout/oversize failures; exact allowlisted argument arrays; minimal environment; no shell/network/write to the source repository; full checks; clean install; audit; Markdown links; complete-diff review; and protected pull-request plus post-merge CI.

## Decision

- Keep Git collection implementation-internal to `@fork-me-up/community-provider`. Protocol, Core, Provider, MCP, and adapters receive no Git command, path, identity, or snapshot type. Accept only a live private authority issued by M2-S01 and reauthorize the stored root and repository before any Git-specific access.
- Support only a standard non-bare working tree whose `.git` and `.git/objects` are real directories physically contained in the selected repository. Reject `.git` files, worktree/common-dir indirection, symlinks/junctions, special entries, object alternates, and unsafe control paths. Submodules and nested repositories remain boundaries, not recursively collected sources.
- Resolve `HEAD` without invoking Git: bounded read-only handles parse a detached object ID or a bounded symbolic `refs/heads/*` chain, falling back to a bounded validated `packed-refs`. Read an optional bounded `shallow` boundary. Require one consistent 40-character SHA-1 or 64-character SHA-256 object-ID format and safe ref syntax.
- Snapshot the complete reachable object-store directory structure before and after Git plumbing. Sort names; enforce the configured entry, depth, byte, and duration ceilings; require every canonical entry to remain within both the selected repository and `.git/objects`; reject every link/special entry and `info/alternates` or `info/http-alternates`; and require the two metadata fingerprints to match. This detects static escape and ordinary concurrent replacement but is not a portable filesystem transaction against a malicious same-user process.
- Never run Git against the repository's own Git directory. For each command, create a fresh trusted temporary bare Git directory containing only a fixed configuration and optional validated shallow boundary, set its object directory to the already authorized local object store, and remove it afterward. System/global configuration points to the platform null device, repository configuration and worktree attributes are outside the quarantine, optional locks/replacement objects/lazy fetch/prompts/pagers are disabled, and no remote or credential input is admitted.
- The Node command port accepts only exact argument shapes for `rev-list`, `cat-file --batch-check`, `cat-file --batch`, and `diff-tree` with `--no-ext-diff`, `--no-textconv`, no renames, NUL-delimited names, and explicit object IDs. It uses `spawn` with an argument array, `shell: false`, hidden Windows UI, piped bytes, a minimal environment, bounded stdin/stdout/stderr, a deadline kill, and no returned native diagnostic. The port independently rejects any non-allowlisted command, option, identifier, size, or timeout.
- Traverse at most the smaller of 256 commits and the configured entry ceiling in deterministic topological order. Request one extra object to mark `historyTruncated`; truncation is an explicit bounded success, not silent completeness. Batch-check every selected object as a commit and enforce per-object and total byte ceilings before reading raw objects. Validate raw headers, parents, timestamps, and UTF-8 metadata; treat commit messages only as inert data from which strictly bounded `Co-authored-by` trailer identities are hashed, never emitted or executed.
- For each selected commit, request only changed names through `diff-tree`; emit no patch, blob, file content, line count, mode, rename source, or diagnostic. Validate and normalize every NUL-delimited name as a safe forward-slash repository-relative path, sort/deduplicate it, and bound total path associations and bytes. Merge commits retain all validated parent IDs; path associations are descriptive collection metadata, not proof of individual authorship.
- Emit only immutable `git-metadata-snapshot` `0.1.0` records: opaque configured repository/root IDs; `sha1` or `sha256`; `HEAD` object ID; explicit truncation/shallow booleans; total selected commit bytes; and sorted commit records containing object ID, parent IDs, canonical UTC authored/committed timestamps, lowercase SHA-256 author/committer/coauthor identity digests, and safe changed paths. Names, emails, messages, trailers, branch/ref names, remotes, URLs, absolute paths, local configuration, stdout/stderr, and native errors are never returned.
- Return all-or-nothing success or only `invalid-input`, `path-unavailable`, `not-authorized`, `unsupported-repository`, `git-unavailable`, `invalid-metadata`, `limit-exceeded`, or `deadline-exceeded`, plus retryability. No error contains repository IDs, object IDs, paths, identities, source text, messages, command output, exit codes, stacks, or partial records.

## Consequences and alternatives

Quarantine makes repository-controlled aliases, includes, hooks, filters, pagers, fsmonitor, diff/textconv drivers, replace refs, credentials, and remotes irrelevant to the invoked plumbing instead of attempting to enumerate every possible Git configuration key. Explicit object IDs and a separate trusted Git directory also prevent local refs or config changes from silently changing the selected history after `HEAD` resolution. Identity digests preserve a later comparison boundary while keeping names/emails out of the snapshot; M2-S04 must still distinguish configured developer, coauthor, bot, shared, squash, pair-work, and unknown states and cannot treat a digest or changed path alone as ownership proof.

Standard-layout restriction excludes linked worktrees, submodules selected as independent repositories, bare repositories, alternate object stores, and some large histories. The 256-commit prefix is deliberately marked when incomplete. SHA-256 repository support is structurally defined but Windows integration proof depends on the installed Git build. Object-store before/after fingerprints reduce races but cannot make multiple external reads atomic against a hostile process with the same operating-system authority; Community source selection assumes the owner's local repository is not under active adversarial mutation during collection.

Running normal `git log`, trusting `.git/config`, scrubbing only a few known configuration keys, using a shell command, emitting author identities or messages, following alternates/worktrees, fetching missing objects, reading patches/blobs, invoking `status`, executing attributes/filters, and silently swallowing command/parse failures are rejected. A Git library dependency is also rejected for this slice because the installed allowlisted plumbing plus quarantine supplies the required bounded metadata without changing the package graph.

## Validation

Run the pinned Windows Node.js/npm path and `npm run check`. Unit tests inject Git-command and clock outcomes to verify exact command allowlists, parsing, hashing, truncation, limits, deterministic immutable output, and content-free failures. Integration tests create only temporary synthetic repositories with local Git commands, then collect with the real Node boundary under hostile config, hook, include, attributes, pager, fsmonitor, diff/textconv, replace-ref, message, identity, path, merge, shallow, symlink, alternate, oversized, timeout, and unavailable cases where supported. Static inspection rejects shell, network, remote/fetch, repository writes, and uncontrolled command forms. Review output fields for raw identities/messages/absolute paths, confirm no manifest/lockfile/public-schema change, validate Markdown links and dependency audit, then require protected pull-request and post-merge CI before the proposed queue transition becomes authoritative.
