# ADR-0021: Explicit conservative Git authorship assessment

- Status: Accepted
- Date: 2026-09-05

## Context and task contract

M2-S03 is integrated on protected `main` at `4f7dfaf`, making M2-S04 the earliest eligible slice. Authenticated GitHub and local readback found successful current-`main` CI, no open pull request, no competing branch or worktree, and a clean tree. This task is claimed by `feat/m2-s04-authorship-assessment`.

Traceability is `M2-S04`, `FMU-FR-006`, `FMU-FR-018`, `FMU-NFR-005`, `FMU-NFR-006`, `FMU-NFR-011`, `FMU-E-008`, UC-05/UC-07, PROJECT_SPEC Sections 11 through 15, PROTOCOL Sections 2.1 and 5.2/5.3, ARCHITECTURE Sections 5.2/5.3 and 12, SECURITY_PRIVACY T-04/T-05/T-06 and Sections 8/10/11, ENGINEERING Sections 3 through 8, ADR-0008, and ADR-0020. The observable result is that explicit private developer identity configuration plus an M2-S03 snapshot deterministically produces a sanitized per-commit authorship assessment that distinguishes attributed, shared, coauthored, bot, pair-work, squash, merge, and unknown conditions while preventing any single assessment, especially shared or unknown authorship, from supporting high-confidence `demonstrated-depth`.

In scope are an implementation-internal versioned identity configuration resolver, shared Git identity normalization/digest logic, a pure authorship assessor, immutable private output, synthetic unit/integration fixtures, `FMU-E-008`, this ADR, and synchronized architecture/security/README/changelog/roadmap documentation. Hard non-goals are automatic identity discovery, heuristic bot-name matching, raw identity output, Claim or Evidence production, capability/depth inference, fork/template/generated/vendor/tutorial/duplicate classification, correction precedence, persistence, owner CLI, Provider/MCP/adapter changes, public schema changes, dependencies, network access, source writes, release, or migration.

The configuration and assessment begin at implementation-internal version `0.1.0`. No released or persisted data requires migration. Allowed effects are local source/document edits, temporary synthetic repositories, deterministic checks, a short-lived branch, the already authorized pull request/squash merge, and branch deletion. Stop on a higher-authority conflict, raw identity or repository content in output/errors, an inference that upgrades uncertain authorship, a public-contract/dependency change, ownership conflict, unresolved high-severity finding, or protected CI failure.

Required verification covers exact closed configuration shape/version/byte/count/string limits; normalization equivalence; duplicate and cross-role identity rejection; opaque subject and repository identifiers; SHA-1/SHA-256 annotations; forged resolved configuration; exact snapshot validation; deterministic order and immutability; attributed/shared/coauthored/bot/pair-work/unknown states; ordinary/merge/squash shapes; bot involvement, unmatched coauthors, shallow/truncated limitations; conservative Evidence-authorship mapping; standalone depth/confidence ceilings; dangling annotations; malformed and canary identity data; content-free failures; integration with the real M2-S03 digest output; offline/no-execution static inspection; full checks; clean install; audit; Markdown links; complete-diff review; and protected pull-request plus post-merge CI.

## Decision

- Keep identity configuration and authorship assessment implementation-internal to `@fork-me-up/community-provider`. Protocol, Core, Profile Provider, MCP, and adapters receive no raw identity, configuration, Git snapshot, or assessment type in this slice.
- Resolve at most 32 KiB of exact JSON `0.1.0`. Require one opaque target `subjectRef`, one or more explicit Git identities, and optional bounded commit annotations. Each identity supplies private name/email input and exactly one role: `developer`, `shared`, or `bot`. Normalize name/email exactly as M2-S03, replace each pair immediately with its lowercase SHA-256 digest, sort the resolved records, reject duplicate digests even across roles, and never retain or return the raw input.
- Use only explicit bot and shared-identity roles. Do not infer a bot from a name pattern or infer a shared account from frequency. Optional annotations identify a repository/object ID and mark `pair-work` collaboration or `squash` history. They are scoped to the configured developer and are limitations/attribution context, not declarations of capability or depth.
- Validate the complete private `git-metadata-snapshot` shape and limits again at the pure assessment boundary. Require one object-ID format per repository, canonical UTC timestamps, unique repositories/commits, valid identity/coauthor digests, bounded parents and paths, and annotations that resolve to an included repository/commit. Invalid or mismatched input returns no partial assessment.
- Classify target participation deterministically. An explicit pair-work annotation takes collaboration precedence. Otherwise a developer identity as author with coauthors, or a developer identity in coauthor trailers, is `coauthored`; a developer author without coauthors is `attributed`; an author using a configured shared identity is `shared`; an explicitly configured bot author is `bot`; and every unmatched case is `unknown`. A bot coauthor/committer is retained only as a structured limitation and cannot erase recognized developer participation.
- Represent history independently as `ordinary`, `merge`, or explicit `squash`. A squash annotation takes precedence over the structural merge signal. This prevents a squash workflow from being mislabeled as an identity and avoids pretending Git topology can infer squashing reliably.
- Map only `attributed` to Evidence `attributed`; recognized target collaboration (`coauthored` or `pair-work`) to Evidence `coauthored`; `bot` to Evidence `bot`; and `shared` or `unknown` to Evidence `unknown`. Shared identities do not prove which user acted. Only mapped attributed/coauthored states carry the configured opaque subject reference.
- Emit a fixed limitation enum set rather than free text. Every commit explicitly carries `standaloneDemonstratedDepthAllowed: false`. An ordinary/merge attributed commit has at most `practical-use` and `medium`; coauthored/pair-work has at most `exposure` and `low`; squash further caps support at `exposure`/`low`; and shared, bot, or unknown has no personal-depth ceiling and only low confidence. Later evidence/claim slices may aggregate repeated qualitative signals but may not reinterpret these ceilings as proof.
- Return only immutable `git-authorship-assessment-snapshot` `0.1.0` data: repository/object IDs already present in the private Git snapshot, canonical observation time, structured attribution/history states, mapped Evidence state plus optional opaque subject reference, fixed limitation codes, and conservative ceilings. Names, emails, raw commits, paths, messages, identity config, and native diagnostics remain absent.

## Consequences and alternatives

The owner can explicitly map multiple Git aliases without exposing them downstream, and later Evidence normalization receives an exact conservative authorship basis. Shared logins, trailers, bots, pair work, squash history, merges, shallow/truncated history, and unknown identities remain distinguishable instead of collapsing into a binary owner/not-owner result. The cost is deliberate configuration: unlisted identities remain unknown, and pair/squash meaning is never guessed from names, commit messages, topology, or hosting-provider conventions.

Raw identity retention is rejected because later matching needs only the same digest boundary already emitted by M2-S03. Name-pattern bot heuristics and automatic email discovery are rejected as brittle and privacy-expanding. Treating a committer match as authorship, treating changed paths as ownership, mapping shared identities to the configured subject, inferring squash from topology, or promoting a single attributed commit to demonstrated depth are rejected as overclaims. Changing the public Evidence schema is unnecessary because the assessor conservatively maps its richer private states into the existing authorship enum.

## Validation

Run the pinned Windows Node.js/npm path and `npm run check`. Unit tests exercise resolver and assessor boundaries, every state/shape/ceiling, normalization, exact limits, ordering, immutability, malformed/forged input, dangling annotations, and content-free canary failures. Integration tests create only temporary synthetic repositories, collect through M2-S03, and prove raw configured identities match the collector's digests for attributed, coauthored, bot, pair-work, squash, and unknown cases without output leakage. `FMU-E-008` asserts that shared and unknown cases never permit high-confidence personal depth. Static inspection rejects process, filesystem, network, dynamic-code, and raw-identity output paths in the pure modules. Review the complete diff, dependency/lockfile/public-schema stability, local links, and vulnerability result, then require protected pull-request and post-merge CI before the queue transition becomes authoritative.
