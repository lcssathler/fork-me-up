# ADR-0039: Local-first bounded public repository history

- Status: Accepted
- Date: 2026-09-09

## Context and task contract

M3-S05 is integrated on `main` at `e21bf84` with successful pull-request and post-merge CI. The owner authorizes M3-S06 to implement optional, limited public-history access through both existing paths: prefer local Git, and permit GitHub only through existing authentication plus explicit consent. The feature remains opt-in, read-only, creates or persists no credential, and cannot make network or GitHub access a requirement for the local runtime. The slice is claimed on `feat/m3-s06-public-history` with no competing pull request, branch or worktree.

Traceability is `M3-S06`, `FMU-FR-002`, `FMU-FR-016`, `FMU-FR-026`, `FMU-NFR-004`, `FMU-NFR-005`, `FMU-NFR-007`, `FMU-NFR-008`, `FMU-NFR-011`, `FMU-NFR-012`, UC-05/UC-11, Architecture Section 4.2, Security T-01/T-03/T-04/T-08/T-10, and ADR-0003/0018/0020/0021/0022/0026/0030. Existing `FMU-E-007`, `FMU-E-008`, `FMU-E-012`, `FMU-E-014` and `FMU-E-015` retain the applicable behavioral limits; no new evaluation ID is introduced because the slice supplies the same private Git metadata shape to the existing authorship, risk and Claim pipeline without changing Claim or DCP semantics.

The observable result is an owner-configured local refresh that always attempts the selected repository's existing local Git history first. A complete local history makes zero GitHub calls. When local history is shallow, or an eligible local Git path is unavailable with an exact configured head, a valid temporary consent may read the explicitly mapped public GitHub repository through an already authenticated `gh` installation. The refresh reports the history source, fixed GitHub status and request count; repeated unchanged refreshes use only the existing process-memory source cache.

In scope are an implementation-internal consent/configuration boundary, a fixed GitHub REST read port, local-first orchestration, sanitized conversion to the existing private Git snapshot, owner-visible refresh metadata, deterministic synthetic tests, package staging, documentation and this security ADR. Public schemas, Core, Provider/MCP operations, profile/export/store formats, dependencies and source-risk meaning remain unchanged. Private repositories, OAuth or GitHub App creation, token input/storage, unauthenticated HTTP, arbitrary hosts/endpoints, webhooks, issues/pull requests, source writes, persistent remote-response caches, live-network tests, publication and release are excluded.

## Decision

- Absence of the optional `publicHistory` configuration preserves the existing offline workflow. Presence is a closed `0.1.0` owner configuration with `local-first` mode, fixed `existing-gh` authentication, fixed `public-metadata-read-only` permission, explicit repository mappings and the exact `allow-read-selected-public-history` decision. Consent carries canonical issue/expiry times, lasts at most 24 hours, and is removed or allowed to expire to revoke future network use.
- Bind the resolved public-history authority to the exact live local repository authorization that issued it. Each GitHub mapping names one already selected opaque repository ID, a validated `github.com` owner/repository pair and an optional exact SHA-1 head. No token, URL, hostname, account identifier, scope override, arbitrary header or credential path is accepted.
- Run the existing quarantined local Git collector first. A non-shallow successful snapshot ends collection without invoking the GitHub port. GitHub may enrich a shallow result using its exact local head. It may replace an eligible unavailable local Git path only when the owner supplied the exact expected head. Authorization, malformed-metadata, limit and deadline failures do not gain a remote bypass.
- The Node GitHub port invokes only `gh api --method GET --hostname github.com` with fixed API headers and one validated relative repository/commit endpoint. It uses `shell: false`, hidden Windows UI, disabled prompts/pagers, bounded stdout plus stderr and a deadline kill. The port neither accepts nor reads a token itself; `gh` owns any pre-existing authentication outside Fork Me Up. Nonzero or missing `gh` results are content-free unavailability. There is no automatic retry.
- Verify `private: false`, `visibility: public` and the exact selected repository name before reading history. Traverse at most 64 commits and 257 total requests, with at most four 100-file pages per commit, 4,096 changed paths, 1 MiB per response, 16 MiB total response bytes and 60 seconds. Configuration can only lower these ceilings and must remain within the selected local repository's existing byte/file limits.
- Accept only SHA-1 object IDs, bounded parent graphs, canonical timestamps, valid Git identities and safe repository-relative changed paths. Commit messages are untrusted and used only to derive bounded coauthor identity digests; names, emails and messages are discarded immediately. The resulting private `git-metadata-snapshot` contains only opaque local repository/root IDs, object IDs, timestamps, identity digests, parent relationships and safe paths. It contains no GitHub owner/name, URL, token, raw response, source content or native diagnostic.
- A private/mismatched repository, head mismatch, malformed response, unsafe path, exhausted limit or invalid consent returns no remote snapshot. If a valid local snapshot already exists, optional GitHub failure falls back to it without reducing security. Otherwise collection returns a typed content-free failure and no partial source set.
- Reuse the existing incremental refresh cache only in process memory. Cache hits make zero local Git commands and zero GitHub requests. Store persistence continues to contain only existing derived Evidence/Claims and never credentials or raw remote responses. Owner refresh output exposes `historySource`, a fixed `githubStatus` and aggregate `networkRequests`; MCP consumers cannot request collection or network use.

## Consequences and validation

The Community runtime remains fully useful without GitHub, `gh`, an account or network. Public history can add bounded attribution context for a shallow selected repository without turning remote availability into authority or allowing a consumer to trigger ingestion. The trade-off is deliberate: GitHub support is limited to `github.com`, public repositories, exact commit history and an external existing `gh` login. It does not establish GitHub App, private-repository, issue/PR, webhook, OAuth, persistent-cache or hosted-service compatibility.

Verification uses only temporary synthetic local repositories and injected GitHub byte responses; no test uses a real credential or network call. Unit coverage proves exact consent/configuration, authority binding, local-first zero-network behavior, expiry, public visibility, exact head, malformed/canary response rejection, bounds, fixed GET endpoints and content-free fallback. Refresh/runtime tests prove owner-only configuration, visible request/source state and zero-request memory-cache reuse. Static inspection rejects write methods, arbitrary URLs, shell invocation, credential fields and persistent remote output. Run focused tests, formatting, lint, type checking, schema/unit/integration/evaluation checks, package/compatibility/lifecycle regression as applicable, dependency audit, documentation checks and one final `npm run check`; required pull-request and post-merge CI remain mandatory before the roadmap transition is authoritative.
